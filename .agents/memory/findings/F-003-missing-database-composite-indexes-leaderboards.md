# Finding (F-003) - Missing Composite Database Indexes on Leaderboards Schema

## 1. Description & Context

The Leaderboards API queries global rankings with sorting and tie-breaking:
* High-score arcade boards: `WHERE game_id = ? AND leaderboard_id = ? ORDER BY score DESC, updated_at ASC`
* Time-trial boards: `WHERE game_id = ? AND leaderboard_id = ? ORDER BY score ASC, updated_at ASC`

---

## 2. Root Cause Analysis

In [`portal/backend/src/schema.ts:56-67`](/portal/backend/src/schema.ts),[^schema-backend] the `leaderboards` table is defined as:

```typescript
// portal/backend/src/schema.ts:56-67
export const leaderboards = pgTable("leaderboards", {
  userId: integer("user_id")
    .notNull()
    .references(() => users.id, { onDelete: "cascade" }),
  gameId: text("game_id").notNull(),
  leaderboardId: text("leaderboard_id").notNull(),
  score: doublePrecision("score").notNull(),
  metadata: text("metadata"),
  updatedAt: bigint("updated_at", { mode: "number" }).notNull(),
}, (table) => ({
  pk: primaryKey({ columns: [table.userId, table.gameId, table.leaderboardId] }),
}));
```

### The Flaw:
* The only index generated by PostgreSQL is the composite primary key `(user_id, game_id, leaderboard_id)`.
* Because `user_id` is the leading column of the primary key index, queries filtering by `(game_id, leaderboard_id)` cannot use the primary key index.
* When querying `ORDER BY score DESC` or `ORDER BY score ASC`, PostgreSQL must perform a **Full Table Scan (`Seq Scan`)** across all rows in the `leaderboards` table and sort rows in memory or on disk (`Sort / Disk Sort`).

---

## 3. Impact

1. Query latency increases linearly $O(N)$ with the total number of players across all platform games.
2. Under concurrent console usage, ranking queries lead to high PostgreSQL CPU load and thread pool exhaustion.
3. Pagination (`LIMIT 10 OFFSET 1000`) becomes slow.

---

## 4. Remediation Plan

Add composite B-tree indexes to `portal/backend/src/schema.ts` supporting both descending (high scores) and ascending (speedrun) ordering:

```typescript
import { index } from "drizzle-orm/pg-core";

export const leaderboards = pgTable("leaderboards", {
  // ... fields ...
}, (table) => ({
  pk: primaryKey({ columns: [table.userId, table.gameId, table.leaderboardId] }),
  descIdx: index("leaderboards_game_board_score_desc_idx").on(
    table.gameId,
    table.leaderboardId,
    table.score.desc(),
    table.updatedAt.asc()
  ),
  ascIdx: index("leaderboards_game_board_score_asc_idx").on(
    table.gameId,
    table.leaderboardId,
    table.score.asc(),
    table.updatedAt.asc()
  ),
}));
```

Execute a schema migration or recreate the container schema using Drizzle.
